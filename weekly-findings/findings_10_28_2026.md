## Client-sideXMLsanitization/客户端侧XML清洗

Observed/confirmed finding: XML sanitization happens only client-side on the UI in the Bambu Lab client. The UI does not display XML tags to the user. However, the raw XML tags are still sent in the API requests and are processed by the LLM as part of the prompt (as confirmed by the promptfoo testing screenshots).

This is important because it means the "sanitization" is only a presentation-layer filter, not a true security boundary. Direct API calls or alternate client paths bypass this UI filtering entirely, sending raw XML directly to the LLM. This creates a potential vulnerability where malicious or unintended XML tags can be injected and processed by the backend model, even if they would not be visible or executable in the normal web UI.

观察/确认的发现：XML清洗仅发生在BambuLab的UI客户端侧。界面上不会向用户显示XML标签。然而，在直接发起API请求时，原始XML标签仍会被发送，并作为提示词的一部分被LLM处理（已通过promptfoo测试截图确认）。

这一点很重要，因为这意味着所谓的“清洗”仅仅是表现层的过滤，并非真正的安全边界。直接API调用或替代客户端路径会完全绕过这种UI过滤，将原始XML直接发送给LLM。这产生了一个潜在漏洞：即使某些XML标签在普通WebUI中不可见或无法执行，它们仍可能被注入并由后端模型处理。

Another finding this week is that making the LLM output its reasoning process may also cause it to accidentally reveal its system instructions. In several runs, the model disclosed more system- level information when asked to reason step by step.

本周的一个关键发现是：让LLM输出其推理过程，也可能导致它意外泄露系统指令。在多次运行中，当要求模型逐步推理，模型披露了更多系统级信息。

Asking the chatbot to output its reasoning in a <thought> block was useful in two ways:

要求聊天机器人在<thought>块中输出推理过程有两个用处：

Key takeaway: explicit requests are not always necessary. Indirect elicitation methods such as sentence accumulation, reasoning prompts, and <thought> blocks can produce more leakage than direct asking.

关键结论：显式请求并不总是必要的。诸如句子累积、推理提示词和<thought>块等间接引导方法，可能比直接询问产生更多的信息泄露。
